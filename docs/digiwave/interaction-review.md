# DigiWave 当前交互评估

本次评估基于当前代码、浏览器操作复现和实际窗口尺寸检查。优先级按“可能损失内容 → 容易误操作 → 使用效率 → 扩展能力”排列。性能建议属于代码层面的风险判断，未作为大工程压测结论。

## 本轮已经处理

| 项目 | 原先行为 | 本轮结果 |
| --- | --- | --- |
| 隐藏分组标注的生命周期 | 折叠一个含标注的分组，再删除组外信号，隐藏信号仍存在，但其注释和连线会被清理。浏览器复现得到：信号存在，连线和注释均变成 0。 | 标注清理改为遍历完整信号树，不再只看当前可见行；回归测试已覆盖。 |
| 边沿消失后的连线 | 将“高—低—高”的低电平改为高后，真实边沿只剩 0 和 30ns，连线仍停在 10 和 20ns，端点没有可见依附点。 | 若仍有连线或标尺依附，原位置自动保留为独立锚点；没有依附的相同电平仍正常合并。 |
| 没有可直接学习的示例 | 用户必须先理解模式和快捷键，才能画出有意义的图。 | 导入入口加入 6 个可编辑协议工程；支持加载、下载 JSON、未保存确认和撤销加载。 |

## 建议下一步优先处理

### P1：模式、确认和待写值不够直观

- View / Edit / Insert 主要依靠快捷键切换；底部模式块外形像按钮，却不能点击切换。
- Binary 在 Edit 中回车应用后也会调用待写值翻转逻辑。用户再次按回车，可能把刚改好的电平改回去。这种自动交替适合连续绘制，但不适合修改已有值。
- 总线先进入 Edit，再按 V 输入，再回车；Esc 先退出数值输入，再退出 Edit。底部提示已减轻记忆负担，但操作步骤仍多。

**建议：**增加可点击的 View / Edit / Insert 切换；Edit 确认后保留待写值，将“自动 0/1 交替”作为 Insert 的可选行为；显示明确的“待写值”和确认动作。

### P1：工具栏与提示区占用画布较多

本次测得：1400×900 窗口中，工具栏约 169px；600×900 窗口中约 301px，叠加展开的编辑提示后，可用画布约 369px。具体数值会随选中模式和提示长度变化。

图标放大后更容易点击，但在窄屏下会把经常一起使用的按钮拆到不同行。状态文字占用了按钮的排列空间。

**建议：**保留当前大图标偏好，同时提供 100% / 150% / 200% 尺寸选项；按“文件、编辑、标注、视图”分组，把低频功能收进菜单；状态文字移到状态栏。底部完整提示保留可折叠，并提供一行精简模式。

### P1：保存、视图状态和工程状态需要分开

- 当前自动备份只有一个槽位，加载示例或其他工程会更新这个槽位。
- 导出固定文件名，多个工程容易混在一起。
- 缩放比例、分组展开和便签折叠也保存在工程里。其中缩放在撤销记录里被特殊忽略，但“是否未保存”的比较仍包含缩放，可能出现只浏览后离开也提示未保存的情况。

**建议：**加入工程名称、另存为和最近工程；自动保存显示时间并按工程分槽；“波形数据变更”和“视图偏好变更”分别管理。重要修改仍应主动导出 JSON。

### P1：菜单和表单还不够支持键盘、触摸

- 添加信号菜单主要通过 hover 展开，缺少明确的点击开关与键盘展开状态。
- 新导入面板有 Esc 关闭，但当前对话框没有统一的焦点循环和关闭后焦点恢复机制。
- 网格数字、参考信号网格是两套概念，目前没有统一的开关与优先级可视提示。

**建议：**统一菜单点击/键盘行为，添加 `aria-expanded` 和可见焦点；对话框统一管理焦点；将吸附显示为“关闭 / 固定步长 / 参考信号”，清楚展示当前来源。

## P2：需要打磨的效率问题

| 问题 | 当前影响 | 建议 |
| --- | --- | --- |
| 注释阅读需要 Text 模式 | AXI transaction 的长说明藏在便签里，用户需要先按 T 才能展开，容易以为只有截断标题。 | View 中允许点击便签展开阅读；移动和修改仍需 Text。 |
| 多选编辑的语义不够明确 | 一次键盘操作可能改多个信号，但“哪条是主信号、粘贴如何配对”不够突出。 | 主信号高亮，多选计数；粘贴前展示源/目标通道对应关系。 |
| 总线缺少位宽和范围 | 可以画总线值，但没有位宽、截断提示、按位展开，数值输入也缺少字段级提示。 | 先加位宽、格式与范围校验，再做位展开。 |
| 时间输入不统一 | 时钟已经是数字加单位下拉框，普通插入持续时间仍用文本后缀。 | 所有时间输入统一支持 ps/ns/us/ms 与相同的错误反馈。 |
| 缺少单独的图像导出 | 打印机按钮只是配色切换；当前没有直接导出 SVG/PNG 的功能。 | 增加“当前视图 / 全部波形”导出，并可选择隐藏光标和选择高亮。 |
| 标注删除后的规则需要显式说明 | 删除锚点会同时删除依附的连线/标尺，虽然可撤销，但用户不一定预期。 | 删除前高亮受影响对象，并在提示中显示关联数量。 |

## P2：大工程的性能与维护风险

每次更新界面会构造工程快照，撤销最多保存 100 个完整状态；布局和部分边沿查找使用线性遍历。大量周期、通道和注释时可能增加序列化与布局开销。

**建议：**先建立可重复的长时钟、多通道、多注释性能样本，再决定采用增量撤销、可见区域索引、布局缓存和列表虚拟化；不要仅凭小示例流畅就认定大工程性能已解决。

## 协议示例的使用范围

导入入口提供 AXI4-Lite、AXI4 INCR Burst、AXI-Stream、APB、SPI Mode 0、UART 8N1。它们是可编辑的时序绘图工程，展示指定事务；不是完整协议验证器，也不是可直接驱动硬件的激励文件。

AXI 示例检查了采样边沿、VALID/READY 握手、背压期间载荷保持及 LAST；SPI 检查采样位序；UART 检查起始位、数据位及停止位。AXI4 Burst 示例展示常用字段，省略 CACHE、LOCK、PROT、QOS 等 sideband；不演示多 outstanding 或乱序返回。
